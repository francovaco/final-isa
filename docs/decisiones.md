# Decisiones técnicas y problemas encontrados

## Decisiones

| Decisión                                                                                      | Alternativa descartada                               | Motivo                                                                                                                                       |
| --------------------------------------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **JHipster 8.11** con dependencias parcheadas (Angular 19.2.25, Spring Boot 3.5.16)           | Migrar a JHipster 9 (Spring Boot 4, Angular 22)      | Es la versión usada en la materia; las vulnerabilidades que quedan no aplican y están justificadas                                           |
| **Excepciones de seguridad solo justificadas por ID**                                         | Bajar el nivel de las puertas o ignorar herramientas | Cualquier hallazgo nuevo sigue frenando el pipeline                                                                                          |
| **Reglas de negocio en el backend** (`ReservaService`) y validaciones de ayuda en el frontend | Validar solo en el frontend                          | El backend es la fuente de verdad; el frontend solo avisa antes de enviar                                                                    |
| **Usuario, estado y fecha de creación los asigna el servidor**                                | Tomarlos del cliente                                 | Un socio no puede crear reservas a nombre de otro                                                                                            |
| **Reloj inyectable** (`Clock`)                                                                | `Instant.now()` directo                              | Los tests de unidad fijan la fecha y no dependen del día en que se corren                                                                    |
| **Clima con Open-Meteo** desde el frontend                                                    | Proxy en el backend                                  | API pública sin API key; así el service worker cachea la respuesta. El token JWT no se envía (el interceptor solo lo agrega a la API propia) |
| **Dockerfile multi-etapa**                                                                    | Jib (lo que trae JHipster)                           | `docker compose up` construye la imagen sin Java ni Node instalados; el CI escanea la misma imagen                                           |
| **Un solo `docker-compose.yml`** con app, PostgreSQL y ELK                                    | Usar el `docker-elk` de clase por separado           | Todo se levanta y se configura con un comando, en cualquier máquina                                                                          |
| **Logstash en el puerto 5001** del host                                                       | 5000                                                 | En macOS el 5000 lo usa AirPlay (`ControlCenter`)                                                                                            |
| **Usuarios de ejemplo** `admin/admin`, `user/user` y Kibana `elastic/changeme`                | Contraseñas generadas                                | Decisión del equipo, para la demo y los tests                                                                                                |
| **Contraseñas internas al azar** en `.env` (no versionado)                                    | Contraseñas fijas en el compose                      | No hay secretos en el repo; `start.sh` las genera la primera vez                                                                             |
| **ZAP solo en el CI**                                                                         | También como script local                            | Decisión del equipo                                                                                                                          |
| **Excepciones de ZAP como INFO**                                                              | IGNORE                                               | Siguen apareciendo en el reporte, pero no frenan el pipeline                                                                                 |

## Problemas encontrados y cómo se resolvieron

| Problema                                                                | Cómo apareció                             | Solución                                                                                   |
| ----------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| `MailServiceIT` fallaba al generar la app                               | Primer `./mvnw verify`                    | Faltaban los mensajes de test en español (`messages_es.properties`)                        |
| 39 vulnerabilidades HIGH/CRITICAL en la imagen                          | Trivy image                               | Spring Boot 3.5.16 y librerías parcheadas; 2 justificadas                                  |
| El secreto JWT de producción estaba en el repo                          | Gitleaks                                  | Se lee de la variable `JHIPSTER_SECURITY_AUTHENTICATION_JWT_BASE64_SECRET`                 |
| Offline, la app mandaba al login                                        | Verificación de la PWA                    | Se cachea `/api/account` con freshness y se borra al cerrar sesión                         |
| La caché podía mostrar reservas de otro usuario en el mismo dispositivo | Análisis de la PWA                        | Al cerrar sesión se borran las cachés de datos                                             |
| Después de crear una cancha, la lista mostraba la versión vieja         | Test E2E del catálogo                     | La caché del catálogo pasó de performance a freshness                                      |
| JHipster no incluía `logstash-logback-encoder`                          | Compilación al agregar logs estructurados | Se agregó la dependencia (8.1)                                                             |
| La alerta de app caída daría falsos positivos con la app ociosa         | Diseño de las alertas                     | Log `LATIDO` cada minuto                                                                   |
| Con la CSP nueva la app quedaba **sin estilos**                         | Consola del navegador al endurecer la CSP | Angular usaba `<link onload>` inline; se desactivó `inlineCritical`                        |
| La acción de ZAP ignoraba `.zap/rules.tsv`                              | Primer job DAST en rojo                   | La acción solo pasa el archivo si tiene alguna regla IGNORE; se pasa con `cmd_options: -c` |
| La protección de `main` esperaba nombres de jobs viejos                 | Al renombrar los jobs                     | Se actualizaron los checks requeridos                                                      |
